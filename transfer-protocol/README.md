# Bounded transfer study review package

This separate study asks whether adding the stateful contract repair to corrected reporting earns its complexity across seven predeclared challenges and two search algorithms. Both systems retain base enforcement. Its [protocol](PREREGISTRATION.md) fixes the contrasts, one-percentage-point harm margin, two-percentage-point production margin, 200-root cap and program retirement rule before new development outcomes.

## Small review tasks

1. **Protocol/statistics:** Reconstruct the four root-level contrasts in `gva_transfer/analysis.py`. Check equal weighting of challenges, the strict joint rule, zero-variance handling, the planning SD floor and the complete sample grid. Do not treat the floor as a confidence bound or zero pilot harm as proof of safety.
2. **Mechanics:** Read the equations before reference code; independently implement fixtures for report correction before clipping, appended legal actions, per-person history after a rejected action, longer horizons and nominal-only depth-two previews. The [test suite](../tests/transfer/test_transfer.py) is author-provided evidence, not external validation.
3. **Optimizer/accounting:** Check beam retention, cumulative two-step scores, final-step depth truncation, replica alignment, exact ties and counts of every policy and duplicate evaluator transition. The two algorithms are not cost matched, and neither is an external implementation.
4. **Collection:** Verify pre-outcome seals, disjoint namespaces, all 28 cells per root, hash-chained traces, scalar reconstruction and complete reporting. Use the common [review report template](../docs/REVIEW-REPORT-TEMPLATE.md).

## Reproduction and status

Use the repository's pinned runtime. `python -m gva_transfer.preflight --output <new-directory>` runs deterministic fixtures and archived development cases, not new transfer roots. `python -m gva_transfer verify --phase development --freeze transfer-protocol/DEVELOPMENT-FREEZE.json` verifies the original development seal.

Collection requires an explicit phase, that phase's unchanged seal and `--execute-phase`; phase choice cannot relabel arbitrary roots. The separate confirmation seal will include the calculated sample and seed schedule after the forty-root pilot. Outcomes and status are appended in later commits; pre-outcome files remain immutable. Outside review is invited but will not delay this bounded study.
